# CityFlow Traffic Simulation Experiments

This repository contains CityFlow traffic-simulation examples, grid-network and traffic-flow data, experiment outputs, replay visualization tools, and utilities for generating or converting simulation inputs. The examples include several grid sizes and TRAFI/V2X-related experiment artifacts.

## Repository map

- `examples/` — sample road-network and traffic-flow JSON files, runnable simulation examples, TRAFI scripts, and saved experiment outputs. The `3-4/cityflow/` folder contains a small CityFlow example; other numbered folders contain additional grid scenarios.
- `tools/generator/` — scripts and documentation for generating grid road networks and traffic flows.
- `tools/converter/` — utilities for converting simulation data.
- `tools/debug/` — a small C++ debugging example.
- `simulation-tools/frontend_replay/` — replay visualization and analysis tools, with usage notes in its README.
- `frontend/` — browser-based replay viewer. See [`frontend/README.md`](frontend/README.md).

## Run the small CityFlow example

The example uses the `cityflow` Python module and the JSON files in its own directory. Install or build CityFlow for your Python environment before running it.

```bash
cd examples/3-4/cityflow
python basic_run_cityflow_simulation.py
```

The script creates `config.json` in that directory, initializes the CityFlow engine with `roadnet_3_4.json` and `flow_3_4.json`, advances the simulation for 100 steps, and prints progress every 10 steps.

Other scripts in this folder demonstrate additional usage, including writing vehicle positions to CSV. Check each script before running it: some examples may use local file paths or generate output files.

## Generate a grid scenario

The generator documentation is in [`tools/generator/readme.md`](tools/generator/readme.md). From the generator directory, a basic 3-by-4 grid can be generated with:

```bash
cd tools/generator
python generate_grid_scenario.py 3 4
```

The generator supports options for lane counts, grid spacing, turning flows, traffic-light plans, and output paths. Run `python generate_grid_scenario.py --help` to see the options available in the checked-out version.

## View a replay

For the browser replay viewer, open `frontend/index.html` in a browser. The frontend README also describes the replay download helper and links to the CityFlow replay documentation. Replay visualization and export scripts are documented separately under `simulation-tools/frontend_replay/`.

## Research background and implementation status

The repository's simulation examples use the CityFlow environment. The papers below provide research context; their citation does **not** mean that their algorithms have been implemented in this repository. In particular, the current examples should not be described as a SocialLight reproduction or as a complete implementation of either paper unless corresponding learning and evaluation code is added and verified.

| Paper | Role in this repository | Implementation status |
| --- | --- | --- |
| *SocialLight: Distributed Cooperation Learning towards Network-Wide Traffic Signal Control* | Background for distributed, cooperative traffic-signal control. | Not implemented / not verified in the checked-in examples. |
| *CityFlow: A Multi-Agent Reinforcement Learning Environment for Large Scale City Traffic Scenario* | Describes the CityFlow simulation environment used as the basis for traffic experiments. | The repository uses CityFlow simulation examples; this is not by itself an implementation of the paper's MARL methods or experiments. |

### References

1. *SocialLight: Distributed Cooperation Learning towards Network-Wide Traffic Signal Control.* [ACM Digital Library](https://dl.acm.org/doi/epdf/10.5555/3545946.3598809).
2. *CityFlow: A Multi-Agent Reinforcement Learning Environment for Large Scale City Traffic Scenario.* [ACM Digital Library](https://dl.acm.org/doi/pdf/10.1145/3308558.3314139).

## Data and outputs

CityFlow scenarios use road-network and flow JSON files. The repository also contains generated replay data, reports, plots, and simulation results; these are example artifacts and are not necessarily regenerated by the basic simulation command above. Keep generated outputs separate from source inputs when running new experiments.
